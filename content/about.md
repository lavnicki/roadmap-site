This site is generated from a private study tracker. Every day, a Python pipeline reads a Google Sheet through a read-only service account, and only the ranges it needs: the weekly study schedule, the module checklist and a curated `Publico` tab. It validates the data (dates, hours, statuses and the totals), keeps only the rows explicitly marked for publication in that tab, and writes a JSON snapshot. A static HTML page is then rendered from that snapshot, with no JavaScript and no cookies.

The `Publico` tab works as an allowlist. Nothing is shown unless a row is marked `sim`, so notes, private projects and anything that is not meant for publication never leave the sheet. Before every deploy, each rendered page is scanned for forbidden terms, secret-like strings, personal data and links to non-allowed sites, and an independent job audits the live site and the full repository history every day. That scanner is itself evaluated like a model: a suite of 59 labelled leak cases (forbidden terms hidden with case changes, invisible characters, HTML entities or split tags, fake secrets and personal data, plus clean texts that must not be flagged) has to score 100% recall and precision in CI, next to about 180 automated tests, including end-to-end canaries planted in every private column of the sheet. If any validation fails, the pipeline stops, the previous version stays online and the failure is reported to me by GitHub, so the site is never left half-updated.

The site itself was built with spec-driven development (SDD). A spec with acceptance criteria, a design with its ADRs and the task list live in the repository under `specs/`, and every change after launch went through the same steps: acceptance criterion, ADR, task, code and test. Each task was written to be self-contained and tagged by complexity, so AI coding agents on cheaper models could implement the routine ones, while design, security-sensitive work and every review stayed on the strongest model.
